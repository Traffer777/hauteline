# Hauteline

Рабочая локальная версия магазина по брифу от 8 октября 2026 года. Next.js / React / TypeScript, SQLite на сервере, локальные оригинальные изображения Figma и шрифты Manrope / Unbounded.

## Запуск

Нужен Node.js 24 LTS и npm. В каталоге проекта:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://127.0.0.1:3000. Для проверки оплаты включите `HL_TEST_MODE=1` в `.env.local` и перезапустите сервер. Деньги в этом режиме не списываются.

Первого владельца создаёт сам заказчик на `/setup` во время локального запуска. Стандартных паролей нет. В production этот путь закрыт.

**Доступ в панель на сервере (по SSH):**
- `npm run owner -- create почта "Имя"` создаёт владельца. Пароль спрашивается в терминале, минимум 12 символов.
- `npm run owner -- password почта` задаёт новый пароль, если его забыли. Восстановление по почте заработает после подключения почтового сервиса. Команда завершает все старые входы.
- `npm run owner -- list` показывает, у кого есть доступ.

Сотрудники входят на `/login` → «По почте и паролю», затем открывают `/admin`. Владелец выдаёт роли в разделе «Команда». После создания владельца `/admin` позволяет добавлять товары, размеры и остатки, менять статусы заказов, обрабатывать заявки, загружать баннеры и назначать роли.

## Сборка

```sh
npm run build
npm start
```

Сборка использует стандартный webpack: проверена на этой версии Next.js. Production работает на Node.js, не как статический экспорт. SQLite и файлы загруженных изображений находятся в `.data/hauteline.sqlite`. Нужен постоянный диск; для нескольких экземпляров сервера требуется отдельная работа над общей базой. Перед переносом базы остановите сервер или сделайте SQLite backup, чтобы сохранить WAL. Не выкладывайте базу, `.env.local` и сессии в общий доступ.

Кроме того, выполнена сборка с проверкой TypeScript и проверены основные переходы в браузере на широком и мобильном экране.

Для повторения тестов запустите отдельный dev-сервер с новым пустым файлом базы, `HL_TEST_MODE=1`, `HL_ALLOW_SETUP=1`, отдельным `HL_DIST_DIR` и портом 3001. ## До публичного запуска

Реальные платежи, email, коды входа, Яндекс ID, VK ID и выбор ПВЗ через API перевозчиков пока не подключены: заказчик предоставит реквизиты и доступы после открытия ИП. Заказы и письма сохраняются, но внешние операции не исполняются. В режиме без тестовой оплаты `/api/payment` возвращает сообщение о неподключённом сервисе.

Встроены четыре примерных лота с изображениями из макета. Это не готовый реальный каталог: заказчик вручную заменяет лоты, цены, размеры и остатки. Контакты поддержки нужно заполнить в настройках. Тексты возврата, обработки данных и рекламного согласия пока содержат заглушки и требуют утверждённых текстов заказчика.

Основная страница, карточка, загрузчик и этапы доставки сверялись с доступными контекстами Figma. Для остальных экранов реализовано согласованное поведение, но точная визуальная сверка ограничена лимитом инструмента Figma. Не выдаём эти экраны за подтверждённое совпадение 1:1.

Проект хранит пароли как scrypt-хеши, сессии в HttpOnly cookies; доступ ролей и цены проверяет сервер. Перед публичным запуском нужны HTTPS, резервное копирование, подключение провайдеров, реальные товарные данные и повторная сквозная проверка уже с ними.

### Акции и промокоды · 17.10.2026

Метки акций на карточках («2 по цене 1», «Комплект») и на странице вещи. В корзине — «добавьте ещё на N ₽ до бесплатной доставки».

## Аудит интерфейса, 20.10.2026

Проверка по шести темам: доступность, сетка, тексты, типографика, цвет и анимации. Исправлено так, чтобы макет Figma визуально не менялся.

- **Клавиатура.** Поле поиска в шапке больше не перехватывает фокус. Окно поиска открывается кликом, наведением или вводом букв, набранная буква переносится в окно, а после закрытия фокус возвращается на место. После закрытия меню, увеличенного фото, удаления из корзины и добавления в корзину фокус тоже не теряется. Появились ссылка «Перейти к содержимому» и область `<main>` на главной. Липкая шапка и плашка cookie больше не перекрывают элемент в фокусе. У полей поиска в окне и в меню виден фокус.
- **Движение.** Баннеры на главной не листаются при наведении и фокусе, а при «уменьшить движение» в системе не листаются совсем. Есть кнопка паузы, видимая только с клавиатуры. Подсказки в поиске тоже уважают это системное правило. Эффекты наведения не «залипают» после касания на телефоне.
- **Экранный диктор.**
  - Выбранный размер, выбранный раздел поиска и группы доставки и оплаты озвучиваются.
  - Кнопки в корзине называют конкретную вещь.
  - Ошибки, ответ на промокод и число найденных вещей объявляются.
  - Копия шапки на экране загрузки скрыта от диктора и клавиатуры.
  - У полей форм есть подсказки для автозаполнения (имя, почта, адрес).
- **Кнопка «Оформить заказ»** не отключается полностью. Если нет согласия, она объясняет, что нужно отметить, и переводит фокус на галочку.
- **Тексты.**
  - Везде «почта» и «СМС».
  - Ошибки говорят, что делать дальше.
  - Покупателю больше не видны служебные статусы вроде «ожидает подключения аккаунта заказчика».
  - Пустые корзина, избранное и поиск подсказывают следующий шаг.
  - Удалённую из корзины вещь можно вернуть из уведомления.
  - Подписка в подвале показывает настоящую причину ошибки.
- **Цвет.** Серые подписи с контрастом чуть ниже 4.5:1 немного затемнены — на глаз разницы почти нет. Цвета текста уведомлений тоже чуть темнее. Выключенный переключатель в кабинете получил тонкую обводку.
- **Сетка и типографика.**
  - Оформление заказа и промокод не вылезают за край на 320–1024 px.
  - На планшетной ширине мелкие подписи оформления не меньше 9–10 px.
  - Кнопка «Перейти в корзину» и плейсхолдеры формы поиска помещаются на 320 px.
  - Неразрывные пробелы стоят в «№ 152-ФЗ», «ст. 26.1», «5 минут», перед «₽» и после коротких предлогов в названиях вещей.
  - Цифры в счётчиках одной ширины.

Оставлено на решение заказчика (заметно меняет вид): затемнить подписи с контрастом 3:1 (хлебные крошки, «Удалить», «или через», подписи способов оплаты), сузить колонку текста юридических страниц до ~72 знаков, поднять шрифт полей на телефоне до 16 px (тогда iOS не увеличивает страницу при вводе).

## Безопасность, 01.11.2026

**Можно ли выгрузить базу, зная код?** Нет, если соблюдены два условия ниже. Ни одна страница и ни один адрес API не отдают файл базы. Папка `.data` лежит вне `public` и сайтом не раздаётся. В коде нет ни паролей, ни ключей. Пароли хранятся в виде scrypt-хэша с солью, сессии хранятся в виде хэша случайного токена. Все запросы к базе параметризованы, SQL-инъекций нет. Каждое действие панели проверяет роль на сервере.

**Обязательно на сервере:**
- Запускать через `npm run build` и `npm run start` (`NODE_ENV=production`).
- Не задавать `HL_TEST_MODE=1`. Даже если его оставить, на боевом сервере тестовый режим (оплата-заглушка, коды СМС в ответе) не включится без отдельного `HL_TEST_MODE_PRODUCTION=1`.
- Не копировать на сервер `.env.local` и папку `.data` с компьютера разработчика. Базу лучше держать вне папки сайта (`HL_DB_PATH=/var/lib/hauteline/hauteline.sqlite`) с правами 700.
- Сайт должен стоять за nginx, который передаёт настоящий адрес посетителя: `proxy_set_header X-Real-IP $remote_addr;`. По этому адресу работают лимиты и блокировки. Подставить чужой адрес через `X-Forwarded-For` не получится: сайт берёт `X-Real-IP` или последний адрес цепочки.
- Владельца создают командой `npm run owner -- create`. Создание через браузер (`/setup`) работает только на компьютере разработчика с `HL_ALLOW_SETUP=1`.

**Блокировки входа по паролю.** После 10 неверных паролей подряд с одного адреса вход закрывается на сутки. Если после разблокировки снова 10 ошибок, то на неделю, дальше на месяц. Через полгода без нарушений счётчик ступеней сбрасывается. Дополнительно в один аккаунт нельзя пробовать войти больше 30 раз за 15 минут с любых адресов. Список блокировок и кнопка «Разблокировать» находятся в панели: «Команда» → «Блокировки входа» (видит только владелец). Если владелец заблокировал сам себя, на сервере: `npm run owner -- unban all` или `npm run owner -- unban 1.2.3.4`.

**Ещё сделано по итогам проверки:**
- заголовки безопасности: сайт нельзя встроить в чужую страницу, HSTS, `nosniff`, `Referrer-Policy`;
- роли «контент» и «маркетинг» в разделе баннеров получают только баннеры, без промокодов и реквизитов;
- истёкшие сессии удаляются при каждом входе.
- Первый экран переделан по референсу: плашка «Выкупаем в бутиках Европы, США и Азии», крупный заголовок в две строки (вторая жирная, с переливом), короткое описание со сроками, пунктирные «маршруты» по бокам. По обоим маршрутам летают самолётики (круг за 5 секунд; в начале маршрута проявляются, в конце тают, без скачка), справа мерцает звёздочка ✦. Плашка набрана тонким Unbounded. Всё появляется по очереди, когда первый экран действительно виден.
